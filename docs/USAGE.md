# Conclave 使用指南

> 面向**使用者**。想知道每处取舍为什么这么定，看 [DESIGN.md](DESIGN.md)；想看代码结构，看 [README](../README.md)。

---

## 一、这是个什么东西

一句话：**Conclave 是装在你自己 Mac 上的一个后台程序，它自己去 Azure DevOps 上找活跃的 PR，自己起 Claude 把代码评一遍，把结论记在一本改不了的账本上，需要的话再替你把评论发回 PR。**

平时它只是菜单栏右上角一个图标，不占 Dock、不进 `Cmd+Tab`。点一下图标出面板，看一眼现在在评什么、花了多少额度，再点一下收起。

它做的其实就是三件事：

1. **发现** —— 每 30 秒问一次 Azure DevOps「哪些 PR 是活跃的」，自动去重，不用人肉报 PR 号。
2. **评审** —— 在临时目录里现拉一份源分支，起 `claude` 评一遍，评完把目录删掉。
3. **留痕** —— 谁评的、什么结论、几条问题、烧了多少 token、折合多少钱，全部落进一条带签名的账本，随时能查。

多台机器装上之后可以组成一个 **mesh**（对等网络）：不需要服务器、不需要调度器，每台机器各自算出**同一张席位表**，所以「哪个 PR 归谁评」不需要任何协商。

---

## 二、为什么值得用

我们现在的做法是一个飞书机器人：人把 PR 号发给它，它在**一台**机器上跑 `claude -p "/az-pr-review <PR号>"`。三个痛点，Conclave 每个都正面解决了：

| 现在的痛点 | Conclave 怎么解 |
|---|---|
| 要人肉发 PR 号，**漏掉的就是漏掉了** | 自动轮询所有 project 的活跃 PR，自动发现、自动去重 |
| 同一个飞书应用**不能在多台机器同时订阅事件**（事件被随机分流） | 完全不依赖飞书事件，每台机器主动去问 AzDO |
| 单台机器既是瓶颈又是单点，它一关机全组没有 review | 活儿按规则分散到 mesh 里所有合格的机器；某台超时或失败，席位自动让给下一台 |

除此之外你还白拿几样东西：

- **不会重复烧额度**。幂等键是 `(PR 号, 源 commit)` —— 同一版代码评过就不再评；作者 push 了新 commit 才算新的一版。
- **复审还是原来那台机器评**。它已经读过这份代码、提过这些问题，比换一台从头理解要准。
- **每一分钱都记着**。哪台机器、哪个人、评了哪个 PR、多少 token、缓存命中多少、折合多少钱，终端一条命令就能看。
- **结论可追溯、不可篡改**。所有事件写进一条签名哈希链（账本叫 **Acta**），谁都改不了历史。
- **想压掉 AI 的随机性也可以**。把 quorum 配成 2 或 3，同一个 PR 由多台机器**独立**评，再多数决合并 —— 被三台都提到的问题几乎必然是真问题，只被一台提到的大概率是噪音。默认是 1（只评一次），因为那是成倍的额度。

## 三、它是怎么工作的

### 一次评审走完的六步

```
  ① 发现   每 30 秒：az repos pr list --status active
              ↓
  ② 去重   幂等键 (PR 号, 源 commit) 已经在账本上了？→ 是就跳过，不重复烧 token
              ↓ 否
  ③ 分席位  每台机器用同一个纯函数算出同一张席位表 —— 不需要互相商量
              ↓ 算到自己头上
  ④ 评审   临时目录拉源分支 → 起 claude 评 → 解析出结论 → 评完删目录
              ↓
  ⑤ 合并   票数够了就把多台的 findings 聚类、多数决，算出每条问题的可信度
              ↓
  ⑥ 公布   写进账本；如果打开了「投递」开关，再往真实 PR 发一条评论 + 投一票
```

### 几个词

| 词 | 意思 |
|---|---|
| **Elector（选举人）** | 一台装了 Conclave 的机器。身份是一串 16 位十六进制指纹，由本机私钥算出来 |
| **Acta（会议录）** | 那本账本。一条全局的签名哈希链，每一块都带前一块的哈希和本机签名 |
| **席位** | 「这一版 PR 由谁来评」。由纯函数算出，各机器结果一致 |
| **quorum** | 这一版 PR 要几台机器独立评。默认 1；改动触及支付/认证/密钥这类敏感面时可以自动提高 |
| **mesh** | 组网的那几台机器。UDP 多播互相报心跳，HTTP 互相传区块 |

### 为什么不需要服务器

因为「谁评哪个 PR」是**算出来的**，不是**分配出来的**。

每台机器的心跳里带着自己的状态（在线、正在跑几个活、额度用了多少、有哪些 project 的权限）。席位函数吃这些输入，输出一张表。同样的输入 → 同样的表 —— 所以三台机器各自算，算出来是一模一样的结果，谁也不用问谁。

这也是为什么**心跳必须签名**：伪造一个「我很闲、额度还很多、什么权限都有」的心跳，就能把席位全吸到自己名下然后永不出票，让所有 PR 卡死。

### 有几条硬规则

- **不评自己的 PR**。作者本人的机器直接出局 —— 自己给自己盖章没有意义。
- **额度用过 80% 的机器不再接活**。界面上那条额度条变红的那一刻，就是它停止接活的那一刻。
- **一台机器一次只评一个 PR**。评完才接下一个。

## 四、装它

### 前置条件

| 需要 | 检查方式 |
|---|---|
| macOS | — |
| `az` + azure-devops 扩展，**并且已登录** | `az repos pr list --status active --top 1` 能出东西 |
| `claude`，已登录且有订阅额度 | `claude -p "/usage"` 有输出 |
| `git` 能**免交互**克隆那些仓库 | 见下面那条命令 |
| （源码方式才要）.NET 10 SDK | `dotnet --version` |

**不需要预先 clone 任何仓库** —— 它自己现拉。但 git 必须能在任意目录下免交互克隆，验证一下：

```bash
git -C /tmp clone --depth=1 <某个仓库的 remoteUrl> /tmp/conclave-auth-probe && rm -rf /tmp/conclave-auth-probe
```

要是它卡住等你输密码，就先配全局 credential helper 或者那个 host 的 `http.<url>.extraheader`。

额度判定**不需要任何配置** —— Conclave 自己跑 `claude -p "/usage"` 取真值，零成本、无头。

### 方式 A：拿到打好包的 `.app`

```bash
xattr -dr com.apple.quarantine Conclave.app   # 没签名的话必须先去掉隔离属性
open Conclave.app
```

### 方式 B：从源码跑

```bash
dotnet run --project src/Conclave.App          # 菜单栏常驻（平时用这个）
scripts/package-macos.sh                       # 或者打成 dist/Conclave.app
```

### 第一次启动会在 `~/.conclave/` 下生成

| 文件 | 是什么 |
|---|---|
| `elector.key` | 本机私钥（ECDsa P-256，权限 0600）。**这就是这台机器的身份，别删** |
| `acta.db` | 本机的账本 |
| `work/` | 临时工作区。只在评审期间有内容，评完即删，启动时还会清一遍残留 |
| `electors.allow` | 节点白名单，**需要你自己建**。不存在 = 单机模式（只信任自己） |
| `appsettings.json` | 可选。本机的配置覆盖 |

### 怎么退出

**面板顶栏右上角的「退出」按钮**，那是唯一的入口。

因为它是 accessory 应用（不进 Dock），`Cmd+Q` 在这里是失效的；点菜单栏图标直接出面板、没有右键菜单。关窗口（或切到别的应用）都只是隐藏，后台的轮询和评审照常跑。

## 五、界面怎么看

点菜单栏图标 → 出主面板；再点一下 → 收起。面板**不会**因为你切去别的应用就自己关掉 —— 它是一张要在上面比对几十行数据的表，切出去查个 PR 回来发现它自己没了纯粹是添乱。

面板从上到下四层：

### 1. 顶栏

本机身份（elector 指纹前 8 位 + az 账号）、此刻在评什么、**两个开关**、退出按钮。

| 开关 | 默认 | 什么时候开 |
|---|---|---|
| **自动评审** | 关 | 确认链路通了之后再开。一开机就把所有活跃 PR 全评一遍会烧掉可观额度 |
| **投递到 AzDO** | 关 | 确认合并出来的结论质量可以接受之后再开。开了才会往真实 PR 发评论 + 投票 |

刚装上时**两个都保持关**，先手动点几个 PR 评一评，看看结论质量，再决定。

### 2. 额度与账单条

每个额度窗口各画一条进度条（5 小时会话额度、7 天周额度、按模型细分的周额度），带各自的重置时刻。**过了自己那条线才变红** —— 5h 是 80%，周额度当下是硬顶 95%（周额度的权重临时摘掉了，见 DESIGN）。变红的那条线就是本机不再接活的那条线，所以「界面变红」和「真的停下来」是同一刻。

右边是今日/累计的评审次数、金额、token、缓存命中率。这一区每 30 秒刷新一次，左上角写着「更新于 HH:MM:SS」——数字冻住的时候你得看得出来是没变化还是没在刷新。

### 3. 六张表（tab 上带条数）

从左到右：

| 表 | 看什么 |
|---|---|
| **在线节点** | mesh 里每台机器的额度 / 正在跑几个 / 近 24 小时评了几个 —— 正好是席位权重的三个输入；名字下面那行还有它的 Conclave 版本和 claude 版本（tooltip 里会写明跟本节点是不是同一版） |
| **我的 PR** | 队列里作者是你自己的那些。本机评不了它们（不评自己的 PR），只能指派出去 |
| **PR 队列** | mesh 里所有活跃的 PR 版本：阶段、谁在评、收票进度、结论，以及行内动作按钮。启动时默认停在这张 |
| **评审记录** | 账单。谁评了什么、多少 token、多少钱、缓存命中、分模型明细 |
| **Acta 会议录** | 账本本体的区块浏览器 |
| **通知** | 本机看到的事件收件箱，tab 上的角标是未读数 |

### 4. 状态栏

最后一句状态 + 链长 + 索引冲突数。

## 六、日常怎么用

### 行内的五个动作

每一行右边是这一行现在能做的事。**按钮有三种状态，含义是不一样的**：

- **没画出来** —— 这一行根本没有这个动作，你也没有办法让它有（结论已经出了、席位归别台机器、别人的 PR 不给指派）。
- **灰着** —— 动作在，只是**此刻**点不了。把鼠标停上去，tooltip 会说清为什么（刚点过在等后台、没有空闲的机器可指派……）。
- **能点** —— 就是能点。

| 动作 | 什么时候出现 | 做什么 |
|---|---|---|
| **评审** | 席位在本机、还没结论 | 绕过「自动评审」开关，把这一版排进本机的评审队列。最多 15 秒后开跑 |
| **认领** | 别人的 PR，还没人在评也没人认领 | 声明由本机来评，优先于自动分配。两台同时认领，先到的赢 |
| **撤销** | 你刚认领、还没开跑 | 交回 mesh 自动分配。**开跑之后就撤不了了** |
| **指派** | 只出现在**你自己的 PR** 上 | 把它交给别的机器评，对方点了同意才生效 |
| **日志** | 有人正在评它 | 在表格下面开出实时日志：拉代码、调工具、模型的分析都在里面 |

点过之后那一行的状态徽章会立刻改字（「已排队」「已认领」「等 xxx 确认」），同时这一行的动作会灰掉 —— 后台的编排循环最长 15 秒才转一圈，不这样的话你会以为没点上然后再点一次。

### 场景一：我想让某个 PR 现在就被评

在「PR 队列」里找到它，点 **评审**。最多 15 秒后开跑。想看它评到哪了，点 **日志**。

手上只有一个 PR 号、不想等下一轮轮询，也可以直接命令行：

```bash
conclave review 2878
```

### 场景二：我自己提的 PR 一直没人评

这是**设计如此**：本机不评自己的 PR，而如果 mesh 里只有你一台机器，那这个 PR 就没有任何合格的评审者，它会一直停在「无人可评」。

出路是**指派**：到「我的 PR」这张表，点 **指派**，选一台空闲的机器。对方会在他的面板顶部看到一条金色横幅，点「同意」之后就归他评了。

指派按钮灰着的话，把鼠标停上去看原因 —— 是「mesh 里还没有别的节点」（要去组网）还是「其他节点都在忙」（等一会儿就行），两者的处置完全不同。

对方一直不点，60 秒之后你可以改指派给别人。

### 场景三：别人请我评

面板顶部会出现金色横幅：「xxx 请你评审 2946@476b95ce」，两个按钮 **同意 / 拒绝**。

**它刻意不自动接受** —— 接受意味着别人的评审任务会在**你的机器上跑 Bash、烧你的 Claude 额度**，那是要本人点头的事。

### 场景四：想知道花了多少钱

看「评审记录」那张表，或者终端：

```bash
conclave report                      # 全部
conclave report --since 2026-09-01   # 限定起始日期
```

```
总计 2 次评审 · 555.7k token · 折合 $1.26
缓存命中 92%（命中的输入 token 计价远低于新输入，这个数越高越省）

⚠️  金额是按 API 目录价折算，不是实际扣费。走 Max/Pro 订阅时边际成本为 0。
```

**那个金额不是账单**。它是按 API 目录价折算出来的参考值；走 Max/Pro 订阅时边际成本其实是 0。报表上会一直标着这句话，免得「这个月花了 40 美元」被当成真的要付 40 美元。

### 通知

**「通知」那张表是收件箱，顶栏下面那条 3 秒的提示是即时反馈**，两者互补。

mesh 里的事多半在你不看屏幕的时候发生 —— 有人请你评审、对方接受或拒绝了你的指派、评审出了结论、额度过了门槛。这些只在内存里，不进账本也不广播（要查事实本身，去 Acta 和评审记录），所以**重启就清空**，「清空」按钮也不需要二次确认。

一分钟内同样的内容不会重复记 —— 轮询失败这类问题每轮都复现，不去重会把真正的事件挤出去。

## 七、命令行

```bash
conclave                 # 默认：菜单栏常驻（图标 + 后台服务）
conclave serve           # 无 UI 常驻。只贡献算力的机器用这个
conclave review 2878     # 只评这一个 PR 然后退出（草稿也评）
conclave report          # 账单
conclave tray-selftest   # 自检「点图标 → 出面板」这条原生通路，顺带验呼吸帧读得出、动得起来
```

怎么调到它，取决于你是怎么装的：

```bash
# 装的是 .app
/Applications/Conclave.app/Contents/MacOS/conclave report

# 嫌长就起个别名，写进 ~/.zshrc
alias conclave=/Applications/Conclave.app/Contents/MacOS/conclave

# 从源码跑
dotnet run --project src/Conclave.App -- report
```

命令行和菜单栏那个进程可以同时开着 —— `report` 只读账本，不会打架。

`review` 的退出码给脚本用：

| 码 | 含义 |
|---|---|
| 0 | approve / approve-with-suggestions |
| 1 | reject / wait-for-author |
| 2 | 找不到这个 PR |
| 3 | 执行失败（claude 子进程或结果解析） |
| 4 | 超时前没出结论 |

### 开机自启

```bash
cp scripts/com.liontravel.conclave.plist ~/Library/LaunchAgents/
launchctl load ~/Library/LaunchAgents/com.liontravel.conclave.plist
```

必须是 **LaunchAgent** 不能是 LaunchDaemon —— Daemon 跑在没有图形会话的上下文里，带 UI 的进程在那儿起不来。

## 八、多台机器组队（mesh）

默认是**单机模式**。要组网，三步：

1. **每台机器先各起一次**，记下面板左上角（或日志里）的 elector 指纹 —— 16 位十六进制。
2. **互相把对方的指纹写进 `~/.conclave/electors.allow`**，每行一个，`#` 开头是注释。**必须双向都写** —— 只写单向的话，A 看得见 B，但 B 会把 A 的请求全丢掉，而且丢得很安静。模板见 `scripts/electors.allow.example`。改动即时生效，不用重启。
3. **在 `~/.conclave/appsettings.json` 里打开 `Conclave.Mesh.Enabled`**。

```
UDP 多播 239.255.42.7:47707   ← 签名心跳（谁在线、HTTP 端点、有哪些 project 权限、负载、额度）
HTTP     :47708               ← 区块传播、补链、指派、实时日志
```

**开启后前 40 秒没动静是正常的** —— 它在等 mesh 成员表收敛。连上的标志是日志里的 `发现节点 <指纹> @ http://…`。

### 组网之前必须知道的五件事

1. **别人的评审任务会在你的机器上跑 `Bash`。** 白名单决定「谁的活可以在你这儿执行」。只加同一团队、本来就都有对应 repo 权限的人的机器。
2. **代码会离开本机。** 别人的机器评 payment-center，意味着 payment-center 的完整代码在他磁盘上出现过（现拉、评完即删，但期间确实落盘）。**所以跨部门不要组网。**
3. **每台机器要有自己的 Claude 订阅**，不能共享账号。这是 mesh 规模的硬约束。
4. **只在同一网段内**。UDP 多播不跨网段，远程办公目前连不上（需要固定 IP 的种子节点，还没做）。
5. **升级要整个 mesh 一起升**。心跳格式变过一次，新旧节点会互相验签失败。

## 九、配置

配置四层叠加，从弱到强：

```
程序目录 appsettings.json  →  ~/.conclave/appsettings.json  →  CONCLAVE_ 前缀的环境变量  →  命令行
```

用户目录那份优先于程序目录 —— 装好的 `.app` 里没法改文件，而每台机器的端口、路径都不一样。

**生效配置会在启动日志里完整打一遍**，四层叠加出问题时先看这一行。

常改的几项：

| 键 | 默认 | 说明 |
|---|---|---|
| `PollInterval` | 30 秒 | 多久问一次 AzDO |
| `OrchestratorInterval` | 15 秒 | 编排循环间隔（也就是点了按钮最多等多久） |
| `MaxConcurrent` | 1 | 本机同时最多跑几个评审。**改大不会真的并发**，编排循环有硬闸 |
| `Quorum.*` | 全 1 | 一个 PR 由几台机器独立评。配成 2/3 就恢复多节点合并 |
| `ReviewTimeout` | 15 分钟 | 单个 claude 子进程的墙钟上限 |
| `MaxReviewAttempts` | 3 | 一版 PR 最多烧掉几个席位（超时与失败各算一次） |
| `StickyReviewer` | true | 作者 fix 后仍由上一版的评审者复审 |
| `ProjectAllowList` / `ProjectDenyList` | 空 | 只轮询 / 排除某些 project |
| `AzureDevOpsOrgUrl` | 空 | 留空则读 `az devops configure` 的 organization |
| `ExtraToolPaths` | 空 | `az` / `claude` 装在非常规位置时补路径 |
| `Mesh.Enabled` | false | 关掉就是单机模式 |
| `Lark.Enabled` | false | 结论出来后用飞书私聊通知 PR 作者（要配自建应用的 AppId/AppSecret） |

⚠️ 两个**只用于本机联调**的开关，别留在日常机器上：

- `AllowSelfReview` —— 允许作者评自己的 PR。
- `Mesh.TrustAllElectors` —— 不读白名单，信任所有验签通过的机器。它关掉的是「谁能让你的机器跑 Bash」那道闸。

完整模板见 `scripts/appsettings.example.json`。

## 十、出问题怎么办

**双击图标启动后提示「读不到 az 登录身份」或者「0 个 project」，但终端里一切正常**

从 Finder 启动 `.app` 时，系统只给一个最小 PATH（`/usr/bin:/bin:/usr/sbin:/sbin`），而 `az` 在 `/opt/homebrew/bin`、`claude` 在 `~/.local/bin`，都不在里面。程序内部有兜底（配置 → PATH → 常见安装目录），还找不到就在 `ExtraToolPaths` 里显式写上。

**某个节点的评审全是 Error，日志里是 `API Error: 400 … does not support this model; version X or newer is required`**

那台机器上有**不止一份 claude**，而 Conclave 起的不是人更新过的那一份。典型组合：官方安装器装在 `~/.local/bin`，`/usr/local/bin` 里还躺着一份没卸干净的旧 `npm i -g @anthropic-ai/claude-code`。他在终端里 `claude --version` 看到的是新的（shell 的 PATH 把 `~/.local/bin` 排在前面），Conclave 从 Finder 启动、拿不到他的 PATH，落到兜底目录挑中了旧的那份。

程序现在会自己处理：把找到的每一份都跑一次 `--version`，**挑版本号最大的**，并且多份并存时在日志里留一条警告列出全部。每台机器用的是哪个版本会跟着心跳摊到整个 mesh —— **「在线节点」表里每一行的小字上就能看到**，不用登上去查。所以先看那台机器的日志：

```
info: Conclave.Infrastructure.ClaudeCli[0] claude 2.1.268 · /Users/x/.local/bin/claude
warn: Conclave.Infrastructure.ClaudeCli[0] 这台机器上有 2 份 claude，用的是 …；另外还有：…
```

评审日志里每一轮也会写明用的是哪一个（`claude 启动，会话 c4fb5ba8 · 2.1.268 · /Users/x/.local/bin/claude`），失败时这条信息会一并落进账本的 Error 里。

如果最新的那份本身就太旧，那就是真该更新了：在那台机器上跑 `claude update`。要钉死用哪一个，在他的 `~/.conclave/appsettings.json` 里写绝对路径（配置优先级最高，不参与挑选）：

```json
{ "Conclave": { "ClaudeExecutable": "~/.local/bin/claude" } }
```

**我指派给别人了，对方那边什么都没出现**

先看对方的日志有没有 `丢弃指派消息：xxx 不在白名单` —— 最常见的原因是**白名单只配了单向**。对方拒收时你这边会明确提示「对方离线，或它拒收了」，不会再显示「等对方确认」然后一直等下去。

**我的 PR 一直停在「无人可评」**

这是硬规则：不评自己的 PR。如果 mesh 里只有你一台机器，那它确实没有合格的评审者 —— 用「指派」把它交给别人。

**额度显示「（折算）」**

说明 `claude -p "/usage"` 的真值没拿到（格式变了、或者是 API key 用户），退化成了按预算折算。**折算低报大约三个数量级，别拿它当数**。面板和日志会说明为什么没有真值。

**mesh 里看不见对方**

跨网段是不通的（UDP 多播）。同网段的话，把日志级别调到 Debug 再看 —— 心跳被丢弃的原因（不在白名单 / 验签失败 / 时间戳不新鲜）都是 Debug 级：

```bash
CONCLAVE_Logging__LogLevel__Conclave=Debug conclave serve
```

**它到底会不会自己往 PR 上发东西**

不会 —— 除非你自己打开顶栏的「投递到 AzDO」开关。默认是关的，结论只写进本地账本。

## 十一、现在还做不到的事

老实说清楚，免得踩坑：

- **跨网段不通**。远程办公连不上同事的节点。
- **每次评审都要重新拉一遍仓库**。这台 ADO Server 忽略部分克隆，所以传输量省不掉；大仓库上这是每次评审的固定开销。
- **额度真值靠解析 `/usage` 的文本**，Claude Code 版本升级可能改格式，改了会降级到折算。
- **一台机器一份额度**。同一个人在两台机器上是两份订阅额度，所以用量按机器指纹汇总，不按人。
- **`quorum ≥ 2` 的多机合并还没在真机上跑通过** —— 需要至少两台各有 Claude 订阅的机器。单元测试覆盖了，真机没验过。
- **往真实 PR 投递还没在生产 PR 上看过效果**（`PostToAzureDevOps` 默认关着）。
